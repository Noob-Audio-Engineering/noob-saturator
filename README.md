# Noob Saturator

> **About Noob Saturator.** I wrote it as a humorous, affectionate answer to
> Ableton Live's Saturator, whose six curves and control set inspired it. It is
> a free plug-in from Noob Audio Engineering, built to show what
> [noob-vst-webgui-framework](https://github.com/Noob-Audio-Engineering/noob-vst-webgui-framework)
> can do with a product-sized interface. It is my tribute to work I admire, not
> a parity replacement for the original — and **nothing here claims to beat
> it**, because nobody has measured it. See
> [What this does not claim](#what-this-does-not-claim).

A free waveshaper by Noob Audio Engineering. The plug-in window is the
operating system's web view; what it shows is a Vue single-page app served by
the plug-in itself and driven over the framework's local WebSocket bridge. The
DSP, the parameters and the page are all in this crate; everything reusable is
in the framework.

**The panel shows its own aliasing, measured on the signal going through it.**
Not a specification, not a figure from a bench session that happened once: the
number on the face is of the audio you are playing, now.

## Install it

Every commit on `main` is built for Windows and macOS and published to the
rolling [`latest`](https://github.com/Noob-Audio-Engineering/noob-saturator/releases/tag/latest)
release: a VST3 and a CLAP in one zip, with a checksummed manifest beside them
and a photograph of that build running.

The easy way is the [Noob Plugin
Manager](https://github.com/Noob-Audio-Engineering/noob-plugin-manager), which
installs and updates every plug-in in this organisation and verifies the
checksum before it writes anything. Or take the zip and unpack it into your
plug-in folders yourself.

## What it is made of

| Part | Where | Role |
|---|---|---|
| DSP | `src/dsp/` | The curves, the antialiasing, the resampler, the colour section and the readout. Host-agnostic. |
| Plug-in | `src/plugin.rs` (feature `plugin`) | nih-plug VST3 / CLAP effect. Embeds `web/dist`. |
| Standalone | `src/bin/standalone.rs` | Fake audio thread on demo signals plus the framework's server: interface development without a DAW. |
| Measurement | `src/bin/benchmark.rs` | Writes [`docs/BENCHMARK.md`](docs/BENCHMARK.md). |
| SPA | `web/` | The interface. |

## Build and run

```sh
# 1. The page (once, and after every interface change)
cd web && npm install && npm run build && cd ..

# 2. The standalone, to see it without a DAW
cargo run --release --bin noob-saturator-standalone -- --open

# 3. The plug-in itself. `--features plugin` is not optional: without it
#    cargo builds the library with no entry points and the bundle is a shell.
cargo nih-plug bundle noob-saturator --release --features plugin
```

## Six curves, each with its antiderivative printed

Warm, Round, Soft, Clip, Fold and Gate. Every one ships with its transfer
function `f(x)` and its antiderivative `F₀(x)` on the panel, because the
antiderivative is what makes the device work: the shaper evaluates
`(F₀(xₙ) − F₀(xₙ₋₁)) / (xₙ − xₙ₋₁)` in place of `f(xₙ)`, and that subtraction
of two nearby values is where an implementation either keeps its precision or
loses it.

The curves are mine. I did not copy Ableton's: they are unverifiable, they are
not modelled on anything, and "sounds like Saturator" is a matter of taste
rather than a measurement.

## Measured

[`docs/BENCHMARK.md`](docs/BENCHMARK.md) is generated by the benchmark binary,
and every row names the figure, where it comes from, what this engine measures,
and whether the two agree.

At the expected drive, the worst in-band alias across all six curves and every
sample rate tested is **−85.34 dB**, against a target of −80 dB.

**The end of the drive control misses that target, and the table says so.** At
+36 dB — a gain of 63 into the shape — six rows miss: the wavefolder worst at
−28.64 dB, the rest between −72 and −75 dB. At that setting a shaped waveform's
bandwidth runs past what any practical oversampling factor can contain, so the
miss belongs to the operating point rather than to the implementation. It is
reported because the end of a control's travel is a real condition somebody
will use, and a figure taken only where the device is comfortable is not a
figure.

The dry path is delayed to match the wet one and sums within **0.05 dB**, so
dry/wet is a mix rather than a comb filter. Latency is 120 samples at the
shipped sixteen-times oversampling, reported to the host and compensated
internally.

## What this does not claim

**Nobody has measured Ableton's Saturator** — not me, not the survey behind
this build, not any third party I could find. So this plug-in claims that it
meets **its own** aliasing target, and cites Ableton's manual admitting the
defect in their own words. It does not claim a margin over them in decibels,
anywhere, and the reason is simply that no such measurement exists to support
one. If somebody runs the bench session, the number goes in the table like any
other.
